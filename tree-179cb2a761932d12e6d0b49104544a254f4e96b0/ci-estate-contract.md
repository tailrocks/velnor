# Velnor CI estate contract

Status: current policy snapshot, captured 2026-09-01. This file is the
machine-readable source for the local estate auditor. A policy snapshot is not
live proof that every GitHub restriction, runner assignment, or workflow is
currently correct; live acceptance remains future/evidence-gated.

## Contract

- The estate has exactly 28 repositories in four generated classes: 20 code,
  5 tap, 2 apt, and 1 fixture.
- Generated workflows are byte-identical within each class. Reusable workflow
  building blocks remain lane-neutral.
- Callers expose one plural `lanes` choice with `velnor`, `github`, and `both`.
  Reusable workflows may retain their singular `lane` input; callers derive it
  from `lanes`.
- Policy classes identify the intended default lane: `jackin-project/*` GitHub,
  `tailrocks/*` and `ChainArgos/*` Velnor. The current shared caller overrides
  that policy for `pull_request`, `merge_group`, and `push` by selecting
  GitHub; `workflow_dispatch` uses its `lanes` input, and other events select
  Velnor. This distinction is policy intent versus current trigger behavior,
  not silent failover.
- Public unmerged contributor code uses GitHub-hosted execution until lower
  trust Velnor isolation has live proof. There is no silent failover.
- Trusted Velnor admission is limited to exact approved workflow paths and
  refs, never an entire public repository.
- Every repository requires exactly `ci-required` and `DCO` merge checks.
- Missing workflow capability belongs in Velnor, not in a repository-local
  workaround.

## Live-gated acceptance

The contract becomes accepted only after generated bytes, exact workflow/ref
closure, selected runner-group restriction, JIT assignment, denial behavior,
public-unmerged routing, warm reuse, and scheduled read-only drift checks are
independently read back. Ambiguous closure, inherited restriction, or an
unreviewed removal stops acceptance.

Implementation: `crates/velnor-tools/src/audit_ci.rs` and
`crates/velnor-tools/src/fleet_policy.rs`. Future status and missing proof live
in [future direction](future-direction.md); dated measurements live in the
[evidence record](evidence-record-2026-09-01.md).
