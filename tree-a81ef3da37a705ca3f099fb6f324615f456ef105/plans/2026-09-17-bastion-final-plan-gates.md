## Bootstrap dependency resolution

A3 cannot demand an unimplemented third local provider or a package not yet deliverable. Use a clearly declared generated hosted recovery/bootstrap provider set or already healthy existing execution capacity, with full expected source checks. Do not silently skip an expected local job and call it green; report bootstrap qualification separately. After D3/E, trusted supported Linux defaults are all three and loss of any required provider fails. Keep real required checks and do not bypass branch protection to cross this boundary.

## Source dependencies versus rollout

The unbounded/global-native foundation is developed in parallel with A/B and included before C2, although operational verification is at C2. Rust Scale Set and three-provider features may develop concurrently but must not delay a correct first APT deployment. Every feature deployed after it requires another signed APT package. These are successive releases of one architecture, not competing plans.

## Gate regression

A later generic fix returns to its affected author/verifier pair. Publish tooling before repinning consumers; package host code before upgrading; requalify affected already-migrated repositories before advancing. No repeated full campaign restart for unrelated changes, and no unverified mixed-version state.
