## (2) Proposed replacement scope for F1

Principle: validate generated release correctness; never assert release
absence; never blindly re-disable.

### 2a. Release-correctness validation (replaces clause 6)

F1 regenerates from F-gate typed config and verifies the generated
`release.yml` preserves, at minimum:

- Triggers: tag push `v[0-9]*` only; `workflow_dispatch` exposes `mode:
  validate` drill only; publication is tag-triggered, never dispatched
  (live: build job `if: dispatch`, sign job `if: != dispatch`).
- Build job: dispatch-only drill on `macos-26` (env/toolchain pins travel
  with the job; no secrets).
- Sign job: tag-only; `runs-on: macos-26`; `environment: release-macos`;
  steps build → verify → `desktop-sign-notarize` → `attest-build-provenance`
  on `native/dist/jackin-desktop-*-aarch64-apple-darwin.zip`.
- Secrets surface (by reference, never values): `DEVELOPER_ID_APPLICATION_P12_BASE64`,
  `DEVELOPER_ID_APPLICATION_P12_PASSWORD`, `APP_STORE_CONNECT_API_KEY_P8`,
  `APP_STORE_CONNECT_ISSUER_ID`, `APP_STORE_CONNECT_KEY_ID`;
  vars `JACKIN_DEVELOPER_ID_CERT_SHA256`, `JACKIN_DEVELOPER_ID_TEAM_ID`.
  F1 checks the reference set is complete and environment-scoped; F-gate
  confirms the secrets exist without printing them.
- Single-writer/mutation-serialization posture for the tag publish path is
  stated (ties to open decision D3).
