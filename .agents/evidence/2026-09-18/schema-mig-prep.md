## 3. Pin requirement

MUST target the #912 merge commit on main (full 40-hex SHA), i.e. a
D2-containing merged product. Rationale:

- A pre-D2 pin CANNOT parse the new schema — proven by D2a itself: "the pre-D2
  pin could not parse the new schema, hence the pin-bump commit" (d2a-schema.md
  gates). Pinning anything before the #912 merge fails `--check` and Policy
  validation the same way.
- A branch tip (D2a `d9b9ce45`/`8db9e5ac`) is not merged and has no merged
  product; the Policy pin-render leg requires pin-merged + product exists.

How verified (all three, in order):

1. `git merge-base --is-ancestor <pin> origin/main` → true (pin is on main).
2. Product exists at pin: `resolve_pinned_binary` / `expected_closures(checkout,
   pin)` succeeds — in practice, the D19 guard builds the pin from source and
   `--plain --check --default-branch main .` reports `Generated files are
   current`, exit 0 (D2a gate precedent).
3. Policy validator regenerates the tree with the generator built at pin and
   requires byte-identical output (the `[generator] revision` contract comment).

- The plan-side generator is the pin-built (D2) binary: it parses `providers` /
  `automatic_providers` / `selectors`, runs eligibility + 3-provider fanout, and
  freezes `plan.outputs { units[], excluded[], plan_digest }`.

  `cargo build -p velnor-workflow` ok;
  `--plain --dry-run --default-branch main .` → `Dry-run: 0 files would change`;
  `--plain --check --default-branch main .` → `Generated files are current`.
- Failure mode excluded: old-schema remnants would be `UnknownProvider` /
  unknown-key hard errors (fail-closed, d2-design §2e), not silent drift — so a
  green check IS the parse proof.

### Policy candidate — pin..head closure-clean since config-only

Per candidate-binding.md: Acquire polls `velnor-workflow-candidate-<pin16>`,
the publisher names `velnor-workflow-candidate-<head16>`, and the two
full-digest manifest gates (Acquire == pin, validator == head) jointly require
`pin_candidate == head_candidate` in full. That holds here:

- Closure inputs (`closure.rs:84-91`) are `crates/velnor-workflow`, `Cargo.toml`,
  `Cargo.lock`, `rust-toolchain*`, `.cargo` (+ features/profile footer).
- This PR touches none of them: only `.github-gen/velnor-workflow.toml`,
  generated `.github/**`, `config/fleet/velnor-host.env`, and state. Hence
  `candidate(pin) == candidate(head)` exactly (the #914 rendezvous pattern,
  `pr916-flow.md:134-136`: "name head16 == pin_candidate16 since pin..head
  touches no closure paths").
- Consequence: IF the publisher path triggers at all — note the publisher skip
  gate (`ir.rs:1538-1543`: `head_closure == base_closure` → skip, no publish)
  and the Acquire early-exit (`ci-policy.yml:76-82`: `pin_closure ==
  base_closure` → Stage-0 validator renders, no candidate needed) — then when
  pin==base post-merge-base-advance the early-exit fires and no candidate is
  needed; when pin!=base the names rendezvous and both manifest gates pass.
  Either way Policy is green; there is no third state because no closure-path
  delta exists to split the names.
- Proof: `velnor-workflow policy --workflow-root . --base-revision <base>` →
  11 rules, 0 failed (D2a precedent), plus CI's live Policy run.

## 5. No-legacy completion proof (mechanical grep)

After regen, the following must return ZERO hits across the config + generated
tree (`.github-gen/`, `.github/`, `config/fleet/velnor-host.env`):

```
rg -l 'runners = |automatic = |default_dispatch_runner|velnor_labels|velnor_trusted|pull_request_on_velnor|velnor_rust_needs|velnor_concurrency_group|github_runner|macos_runner|requires_trusted|automatic_lanes|RunnerMode|RunnerLane|DispatchChoice|LaneAdmission|LANE_ADMITTED|"both"' .github-gen .github config/fleet/velnor-host.env
```

Notes:

- This is the tree-side mirror of d2-design §3's `src/` grep gate (which D2
  itself satisfies); together they prove old-keys-fully-removed end to end.
- `requires_trusted` appears in shipped comments today (docker unit); the grep
  covers comments too — stale comments must go, not just keys.
- `"both"` is quoted to avoid English-word false positives; any hit is a real
  old-schema survivor (dispatch default, runners value) and fails the PR.
- Complement (positive proof): `rg -l 'providers = ' .github-gen` hits; every
  generated per-provider job `name:` contains its provider ID verbatim
  (d2-design §2l grep-able invariant).
