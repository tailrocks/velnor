## Exact old-supported contract

The old parser consumes `.github-gen/velnor-workflow.toml` as a strict schema.
`RepoGenerationConfig` and `PolicySection` both deny unknown fields. The
admissible source contract is therefore:

1. Keep the old config schema and all old generator/policy pins. Do not add
   `[policy.validator]`, aliases, or unknown-field relaxation.
2. If typed validator data must be transported before trusted B exists, place
   it in a separate schema-versioned sidecar source and declare only the old
   supported `[[static_files]]` mapping:

   ```toml
   [[static_files]]
   file = ".github/ci/policy-validator.toml"
   source = ".github-gen/policy-validator.toml"
   ```

   The old validator accepts a repository-relative source and a destination
   below `.github/`; old render copies bytes and old `--check` verifies the
   result. The measured sidecar bytes were identical at source and output,
   SHA-256 `9e58c6ea187c9e1bb510b6b43c1513f69c229aa216643ec770ca7f27d8baccb5`.
3. The sidecar must be dormant transport only. Its schema/product/purpose
   (`velnor.workflow-policy-validator.v1`,
   `velnor-workflow-policy-validator`, `policy-validator`, `Linux-X64`) must be
   parsed and authenticated by trusted B later. The sidecar cannot self-attest
   authority, replace the old checker, or authorize candidate semantics.
4. Do not emit the proposed `xcode-27` workflow or change the old semantic
   selector table until B is trusted and the old-policy-to-B required-check
   handoff is in force.

This is a source-admission/transport result only. It does not prove a product
exists, prove a release, satisfy source binding, or authorize a merge.

## Main-push ordering result

The sidecar repairs only the strict source-admission transport problem. It does
not repair the bootstrap authority/order problem:

* Current main `.github/workflows/ci-runtime-products.yml` still triggers on a
  push to `main` and its application matrix still schedules the macOS-ARM64
  cell on `macos-15`. A source-only merge therefore starts the forbidden old
  Mac cell before a post-merge validator B can be published.
* `ci-main.yml` and the base `ci-policy.yml` still run/acquire the old `0dc`
  path. Publishing B after that push does not retroactively transfer the
  already-started required check. A candidate manifest, PR-built binary,
  `--pin-build`, mutable latest, fallback, skipped cell, or application
  three-platform product cannot supply that authority.
* The no-old-Mac/native-obligation rule remains: a later application product
  must retain Linux-X64, Linux-ARM64, and the newest offered macOS native
  label (currently `xcode-27` under the supplied SPEC); deletion, fallback to
  `macos-15`, or silent skip is not equivalent.

The minimum unresolved step remains a protected merge-time/main-only authority
that builds and attests the separate Linux-X64 typed validator from the exact
resulting main tree, performs the scoped old-policy-to-B handoff, then permits
the final tree to carry the complete current macOS-native application matrix.
This probe supplies no such authority and therefore gives **no approval**.
