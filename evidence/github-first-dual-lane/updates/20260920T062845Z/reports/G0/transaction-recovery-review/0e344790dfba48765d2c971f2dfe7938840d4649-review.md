## Source evidence

- `GenerationLock` opens and locks the output-root directory descriptor, then
  `TransactionAnchors::open_with_lock` clones that exact descriptor rather
  than reopening `root` (`src/s2/mod.rs:10366-10394`, `6586-6618`). Journal
  inspection also stats the transaction directory through `lock.directory`
  before opening anchored children (`8225-8293`).
- Locked journal creation uses `mkdirat`/`openat`, `NOFOLLOW`, and syncs the
  journal and output-root descriptors (`7426-7497`). Manifest, snapshots,
  progress, and record capture use the anchors, including anchored progress
  stage/rename (`7605-7805`, `6751-6766`, `7181-7220`).
- Recovery walks records in reverse order and only cleans after every record
  succeeds (`8296-8318`). Cleanup removes only recorded snapshot names and
  fixed journal names, then requires empty `before`/`after` directories and
  removes the journal with `REMOVEDIR` (`8123-8200`); an unknown journal entry
  therefore blocks cleanup instead of being recursively erased.
- Rollback re-captures each mutated path through the same anchors, requires
  exact post-write identity, and restores/removes only entries in `mutated`
  (`9265-9360`). Unrelated user files are not rollback targets. The hostile
  outside-file fixture additionally verifies that an outside file remains
  byte-for-byte unchanged (`22964-23024`).
- Recovery quarantine renames the current pathname to a private name, captures
  and compares its full identity, detects a newly created output before
  publication, validates published bytes/mode, removes quarantine only after
  that validation, and preserves the journal on mismatch (`9751-9964`).
