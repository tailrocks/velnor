- Triggers: `pull_request`, `push` (`main` + tags), `merge_group`, schedule `23 3 * * 0`, `workflow_dispatch`.

  - `ci-native.yml` — jackin
  - `ci-code.yml` — most code repos
  - `ci-tap.yml` — Homebrew taps
  - `ci-apt.yml` — apt publishers
- Public unmerged PRs stay GitHub-hosted (`*-public-unmerged.yml` where present).
- Typical extra dispatch/schedule surfaces: `renovate.yml` (`0 6 * * *`, `RENOVATE_TOKEN` or `GH_RENOVATE_TOKEN`), `reuse-compliance.yml`, `gitleaks-history.yml` (`0 4 * * 1`), `precommit.yml` + public-unmerged twin.

Lane expression is **not uniform**: some consumers send automatic PR/push/merge_group to GitHub and schedule to Velnor; `ChainArgos/blockchain-nodes` sends non-dispatch events to GitHub always. Record the live expression per repo; do not invent a single default.

## Generator constraints implied by this inventory

1. **Do not copy** historical jackin `velnor-workflow.toml` / `jackin-dev.yml` / `construct.yml` bodies.
2. Jackin current `main` is a **velnor-actions native consumer** plus **hand-owned product workflows** (construct, jackin-dev, preview, release, docs, hygiene). `.github-gen` is gone.
3. Role image repos share one callable product: `jackin-role-action` `publish.yml` (multi-arch image, manifest, sign, Docker Hub).
4. Crate libraries need **publish versioned crate** (crates.io), not container publish.
5. Native CLIs need **signed archives + GitHub release + Homebrew/apt channel update**.
6. Apt repos need **signed reprepro + Pages**.
7. Taps need **scheduled package-update + preview metadata**.
8. Fixture repo is a **protocol corpus**, not a product generator source.
9. java-monorepo and velnor still use **velnor-workflow unit graphs**; most other estate repos have moved to **class consumers**. Requirements differ; do not force one shape.
