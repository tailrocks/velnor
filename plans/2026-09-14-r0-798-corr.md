# Plan 2026-09-14: r0-798-corr — broker-taxonomy corrections (follow-up to #798)

Base: origin/main tip f5c515fc (#799). Branch: r0-798-corr. Worktree: /tmp/velnor-798c.

PR #798 ("typed error categories at the broker/completion boundary")
overpromised: its message and plan claimed retry decisions on the
acquire/complete/ack paths derive from `BrokerErrorCategory`, but review
found the retry loops did not all read the taxonomy, and the plan claimed
timeout decisions the taxonomy never covered. This branch makes the loops
actually category-driven, types the remaining in-scope producers, drops the
timeout claim, and records the remaining-untyped-sites list honestly.

## Problem (five in-scope omissions, all fixed here)

1. The `acquire run-service job` attempt-error producer was untyped
   (`github_api_error`, `category: None`).
2. The acquire retry loop decided via the legacy status/chain derivation
   (`acquire_failure_is_transient`), not the category.
3. The complete loop decided via a local `retriable` bool from
   `classify_completion_response`, not the category.
4. The `complete run-service job` exhausted-transient producer was untyped,
   so the journal fell back to status re-derivation on that outcome.
5. The `create broker session` producer was untyped and
   `create_broker_session_with_retry` retried every failure unclassified
   (a 401 burned the whole 5-attempt budget, ~90 s of sleeps, before
   failing).
6. Docs: the #798 plan's Problem statement said "Retry/timeout/abandon
   decisions". Timeouts were never in scope.

## Fix (this branch, strict scope)

`protocol.rs`:

- `classify_acquire_attempt_error(status)`: Transient for 0/408/429/5xx
  (same verdict shape as the legacy derivation, so typing changes
  forensics, not policy), Terminal otherwise. 404/409/422 never reach it
  (they return `Skipped` first); their mapping is defensive totality.
- The `acquire run-service job` producer attaches that verdict. The loop
  now decides via `acquire_attempt_failure_is_transient` (category first;
  unclassified transport failures fall back to the historical derivation).
  `acquire_failure_is_transient` is kept as the documented fallback, and
  the `is_transient_acquire_error` session gate keeps its verdicts.
- The complete loop now classifies each failure to `Some(Transient)` /
  `Some(Terminal)` (`None` only for status-less transport, which fails
  open to retry) and decides on that category; both produced errors carry
  it, so the journal reads the boundary verdict in both outcomes.
- `classify_broker_session_create_error(status)`: 409 -> Conflict,
  retriable shape -> Transient, else Terminal. The `create broker session`
  producer attaches it.
- `complete_retry_delay` extracted with a `#[cfg(test)]` zero-delay
  override, mirroring the acquire hook (the exhausted-budget regression
  test would otherwise sleep ~135 s).

`runner.rs`:

- `broker_session_create_is_retryable` policy (only `Terminal` fails
  fast; Transient/Conflict/unclassified retry as before) and the fail-fast
  arm in `create_broker_session_with_retry`. Same error shape as budget
  exhaustion.

Timeouts: no category-derived timeouts exist or were introduced. Every
timeout on these paths stays a fixed constant (inventory below); the
"timeout" word is removed from the #798 plan's Problem statement in place,
with a correction note appended there.

Preserved (verified in #798 review, unchanged here): fail-fast outcomes
(acquire Permanent after 1 attempt, completion budget-spend on Terminal),
the `is_transient_acquire_error` teardown gate (transient keeps the
session, permanent tears it down), redelivery self-healing (Conflict never
abandons; the `renewjob` oracle still decides ownership), and every error
`Display` (byte-identical messages asserted in tests).

## Behavior deltas (intended)

- Terminal session-create failures (deterministic 4xx, e.g. 401) now fail
  after 1 attempt instead of after 5. Same terminal outcome (session setup
  aborts with the same error shape), faster, less load on a struggling
  control plane. Fixed credentials cannot succeed on a later attempt of
  the same call, so no success is lost.
- Everything else keeps its verdicts: acquire/complete loops decide on
  the same category values the legacy derivations produced; the new
  signal is the category riding on the produced errors.

## Timeout inventory (fixed constants, kept as-is)

- Per-request ceilings: 30 s for acquire, complete, acknowledge,
  session create/delete, and renew; 70 s for the broker poll.
- Retry backoffs: acquire 5–15 s jittered; complete 5·2^(n-1) s capped
  at 60 s; session create 10/20/30 s by clamped attempt.
- One 2 s settle sleep on the skipped-acquire path in `runner.rs`.
